## Entrega

- Módulo Accounting registrado no monólito, prefixo /v1/accounting gateado e
  catálogo declarativo de permissões/role templates. Módulo opt-in, sem seed de
  habilitação nas contas do usuário.
- Emitentes, membros/grants, perfis versionados, diagnóstico retomável, documentos,
  exclusão lógica, revisão, autorização de envio, execução e histórico persistidos.
  SQL isolado nos arquivos store*.go; handler → service → repository.
- Conta/ator do Principal; grants por emitente intersectam RBAC atual, membership e
  módulo. Sem bypass empresarial por admin/agência. Bootstrap de issue explícito,
  separado de manage e de autorização de documento.
- Diagnóstico com unknown/declared; confirmed exige porta EvidenceVerifier de owner
  revisado. Porta implementada/validada por fixture sintética; verifier real é CT-06
  e fica indisponível em runtime até essa integração. Nunca confirmar só pelo cliente.
- Origem Finance pessoal por porta do owner: consentimento, versões e seleção
  explícita de descrição/serviceCode/CNAE/NBS de rascunho/template. Outros operadores
  não leem a fonte pessoal. Origem/versionamento preservados; reimportação explícita.
  Nenhuma senha, sessão, OCR bruto ou alíquota float é copiada.
- Dinheiro decimal string/NUMERIC, validação exata, datas civis e CAS. contentVersion
  diferencia edição de dados de versão de estado; editar valores idênticos também
  invalida aprovação anterior. Não foi implementado cálculo tributário oficial.
- Um motor para NFS-e/NF-e, testado com conectores exclusivamente fake_local.
  Revisão não autoriza envio. Runtime de composição não registra nenhum fake ou
  conector real; produção permanece coverage_unavailable.
- Execute + evento + receipt + job na mesma transação via EnqueueTx. Store/Enqueue
  existentes preservados. Claim fiscal com lease/fence e autorização revalidada;
  timeout/restart só consultam antes de qualquer retomada, sem repetir envio ambíguo.
- Artefatos originais via Storage privado; metadados/hash no banco. Autorização
  persistida não é desfeita por falha de storage. Recuperação tem job próprio e
  pedido idempotente/versionado, sem novo Submit. Status inclui artifactsPending.

## Reproduzir o menor aceite

Usar PostgreSQL16 descartável, nunca banco de uso. A suíte Accounting exige nome
accounting_test*, Finance exige finance_test*, host exige accounting_test_host*.
Jobs deve usar banco separado com core.accounts(id uuid, name text, slug text,
is_active boolean), pois sua suíte FIFO usa esse contrato host e tabela efêmera.
Nenhuma credencial real é necessária; o container de teste não publica porta.

No container Go da rede desse PostgreSQL, em back/, configurar URLs sintéticas
ACCOUNTING_TEST_DATABASE_URL, ACCOUNTING_HOST_TEST_DATABASE_URL,
FINANCE_TEST_DATABASE_URL e TEST_DATABASE_URL, respectivamente. Executar:

```sh
go test -race ./internal/modules/accounting ./internal/modules/finance ./internal/platform/jobs ./internal/platform/app -count=1
golangci-lint run ./internal/modules/accounting/... ./internal/modules/core/... ./internal/platform/app/... ./internal/platform/jobs/...
```

Aceite mínimo: TestExecuteConcurrentReplayCreatesOneCommandAndJob,
TestFiscalFakeOutcomesAndReplay, TestNFEUsesSameFiscalEngine,
TestLostLeaseFencingAndReconciliation e TestConfirmedDiagnosisRequiresReviewedOwnerEvidence.
Não alegar emissão real a partir de authorized em environment fake_local.
