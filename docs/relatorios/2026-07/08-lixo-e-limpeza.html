Veredito: o repositório versionado é saudável e pequeno — ~99% do peso do working tree é dependência ou artefato local corretamente ignorado pelo git (node_modules, dumps, caches de teste, fonte de referência). Ou seja: a higiene de versionamento está boa; o que falta é higiene de disco e sinalização do que é histórico.

Os dois itens que exigem cautela

!
tmp/ — AC-03 P0 — não é lixo comum: 245,35MB são um backup real do banco pré-rename, e há tokens e secret.key em texto no disco. Excluir sem confirmar = perder um backup; manter para sempre = dados reais e segredos esquecidos numa pasta temporária. Ver também 06-segurança, que trata o ângulo de exposição de segredos.
!
erp-source-local/ — AC-18 P2 — o reflexo de "apagar o maior diretório" quebraria o bootstrap do ERP: ERP_SOURCE_KIND=local consome consolidados/ como insumo ativo. A limpeza aqui é de triagem (separar o que o bootstrap usa do que é histórico), não de exclusão.

O que é seguro hoje, sem depender de ninguém

  • back;C — vazio, untracked, resíduo de shell. Zero risco.
  • web-reference/node_modules — 408,41MB regeneráveis de um projeto inativo.
  • .playwright-mcp/ — 109,7MB de artefatos de teste regeneráveis.
  • Caches do qa-bot/ — seguro, desde que se preserve o código do bot.

Somando os itens seguros + tmp/ (após confirmação), chega-se ao ~1,0GB recuperável citado na visão geral (AC-20) — tudo sem nenhum git rm.

Plano de limpeza sugerido

Checklist em 3 ondas, da menor para a maior necessidade de decisão humana. Nenhum destes comandos foi executado — estão prontos para o dono do projeto rodar manualmente (PowerShell para disco, git para versionados).

Onda 1 — sem risco (executável hoje, ~520MB recuperados)

  • Remover o resíduo back;C (vazio, untracked):
    Remove-Item -LiteralPath '.\back;C'
  • Apagar node_modules do front de referência inativo (408,41MB regeneráveis):
    Remove-Item -Recurse -Force .\web-reference\node_modules
  • Limpar artefatos do MCP Playwright (109,7MB):
    Remove-Item -Recurse -Force .\.playwright-mcp\*
  • Limpar caches/artefatos gerados do qa-bot — preservando o código do bot (inclusive perf_audit.py): revisar o conteúdo de qa-bot/ e remover apenas saídas de execução (screenshots, relatórios, caches).

Onda 2 — com confirmação do dono (~254MB + ~1,5MB no git)

  • Validar e então excluir tmp/ (AC-03, 254,18MB): confirmar que omni-rename-20260521_200120/lista-da-vez-before-omni.dump (245,35MB, backup real pré-rename de 2026-05-21) não é mais necessário — o rename foi concluído e o banco atual está íntegro? Só então:
    Remove-Item -Recurse -Force .\tmp
    Se preferir manter o dump, mover para fora do repo e apagar ao menos os segredos: Remove-Item .\tmp\token.txt, .\tmp\full_token.txt, .\tmp\secret.key; Remove-Item .\tmp\runtime_token*.txt
  • Decidir os órfãos versionados (AC-17): se a spec PIX ainda vale, mover: git mv pix-fixo.html pix-mvp.html docs/; se não, excluir junto com os PNGs:
    git rm pix-fixo.html pix-mvp.html mostarda.png themes-smoke.png bi-page.png
    (o histórico do git preserva tudo; ~1,46MB deixam de inflar cada clone)

Onda 3 — organizacional (triagem, não exclusão)

  • Arquivar docs concluídos: git mv docs/codex docs/historico/codex e git rm docs/COMPONENT_INVENTORY_AUTO.md (existe o manual).
  • Confirmar docs/agents/CODEX.md e COPILOT.md com o dono: se os agentes saíram do fluxo, git mv docs/agents/CODEX.md docs/agents/COPILOT.md docs/historico/. ADRs ficam onde estão.
  • Triar erp-source-local/ (AC-18, 493,3MB): listar o que ERP_SOURCE_KIND=local realmente consome (consolidados/ é insumo ativo do migrate bootstrap-erp-store) e mover o restante para armazenamento fora do repo. Nunca excluir em bloco.
  • Decidir o destino final de web-reference/ (o que sobrou após a Onda 1): os fronts ativos são web/, TAVOLA e crow-nuxt; a referência pode ser zipada para fora do repo ou removida.
📌 Regra permanente: quando um novo artefato local surgir (dump, cache de ferramenta, saída de teste), adicionar a entrada correspondente no .gitignore na mesma hora — foi exatamente isso que manteve o .git em 12,63MB até aqui. E reforçando: nada desta página foi executado; os comandos são sugestão para execução manual do dono do projeto.

AC-03tmp/ local com dump real de banco (245MB) e tokens/secret.key em discoP0Esforço: SImpacto: médio›

Problema: tmp/ guarda um pg_dump real de 245,35MB (pré-rename, 2026-05-21) e segredos de teste (token.txt, runtime_token*.txt, full_token.txt, secret.key) — dados reais e credenciais esquecidos numa pasta "temporária". É advisory: a decisão é do dono, porque o dump é um backup.

Evidência: tmp/omni-rename-20260521_200120/lista-da-vez-before-omni.dump — 245,35MB dos 254,18MB do diretório; gitignored em .gitignore:42. Achado canônico da série (P0) — ver também 06-segurança.

Ação recomendada: confirmar que o dump pré-rename não é mais necessário e excluir (Onda 2); se mantiver, mover para fora do repo e apagar os arquivos de token/secret imediatamente. Nunca automatizar sem confirmação.

LX-01Executar a Onda 1 de limpeza (itens sem risco)P1Esforço: SImpacto: médio›

Problema: ~520MB de artefatos locais comprovadamente seguros de remover (diretório vazio back;C, web-reference/node_modules 408,41MB, .playwright-mcp/ 109,7MB, caches do qa-bot) seguem ocupando disco e poluindo buscas/indexação do editor.

Ação recomendada: rodar os comandos da Onda 1 (aba "Plano de limpeza sugerido") — execução manual do dono; nenhum item exige backup prévio.

LX-03Política de artefatos locais e sinalização de históricoP2Esforço: SImpacto: baixo›

Problema: não há regra escrita para o ciclo de vida de artefatos locais (dumps, caches, saídas de teste) nem para arquivar docs concluídos — por isso tmp/ acumulou 254,18MB, docs/codex/ ficou fora de historico/ após o fim dos sprints e dois inventários de componentes convivem.

Evidência: docs/codex/ (6 arquivos, última modificação 2026-06-08) ainda na raiz de docs/; docs/COMPONENT_INVENTORY_AUTO.md (2026-05-23) duplicando o manual. Relaciona-se aos canônicos AC-17 e AC-18 (ambos P2, exclusivos desta página).
